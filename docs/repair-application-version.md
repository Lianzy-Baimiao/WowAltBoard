# 首页应用版本误读扫描版本

## 现象与根因

v1.18.0 的应用更新面板显示当前应用 1.18.0，但保留旧角色快照时，首页仍显示 1.17.3。

独立 Edge/file:// 夹具复现：`homepage=v1.17.3, installed=1.18.0, scanner=1.17.3`。
只改原生应用版本，首页不变；只改快照 `toolVersion`，首页随之改变。排除旧浏览器缓存与原生注入时序后，确认首页、设置说明和旧更新横幅把扫描器版本当成了应用版本。

这是显示来源错误，不代表安装未成功；不应靠改写角色快照或强制重扫来修正版本标识。

## 修复边界

- 统一通过 `AE.applicationVersion()` 读取应用身份：原生安装回执优先，普通浏览器使用完整包内的 HTML 版本元数据。
- 原生值无效时回退包内元数据；两者都未知就明确显示未知，不借用角色数据里的扫描版本，也不把已下载的新版本当成当前版本。
- 完整包构建从 `tools/scan.ps1` 的正式版本填充暂存 HTML 元数据，包括 `-SkipBuild`；增量包使用同一份暂存文件。无需让普通用户联网查询才能显示当前版本。
- 首页、设置说明和旧更新比较使用同一个应用版本。旧 `toolVersion` 保留原值，只在悬停提示里标为「数据扫描工具」。
- 旧查询结果标为「上次检查查到」，不冒充实时最新发布。
- 不修改角色快照、页面宽度、装备/天赋布局或图标。

## 防回归

原有更新器测试验证了更新面板，却没有验证其版本与首页一致；旧设置测试也把“应用版本”塞进了扫描字段，掩盖了这次升级后保留旧快照的场景。

新增独立测试：

- `node tools/check-application-version.js`：应用身份来源、未知/异常版本、下载目标与当前版本分离；实际构建版本为 9.8.7 的临时完整包和增量包，确认旧 HTML 中的 1.17.3 被正确更新，且源目录不被改写。
- `node tools/check-application-version.cjs`：真实 Edge/file://，覆盖保留旧快照、普通浏览器、原生优先、新扫描器配旧应用、非法版本、未知版本、旧更新横幅共 7 个场景；核对首页、更新面板、设置说明一致，并确保个人快照不变、设置宽度仍为 380px。
- `check-update-panel.js` 的应用版本夹具改为真实原生元数据，扫描版本刻意保持不同；原有历史记录/更新链接检查保留。

浏览器测试需要开发环境提供 Playwright，用户运行应用不需要这些工具。
