# 应用内增量更新

## 用户怎么用

本功能面向**整个看板应用**，不是只更新毕业装备数据。范围包括启动器、原生窗口、扫描工具、界面、随版本发布的装备/天赋数据、图标和文档。

1. 用 `魔兽看板.exe` 打开，在 **设置 → 其他 → 应用更新** 点击「检查应用更新」。原生窗口打开时，托盘「检查更新」也会进入这里。
2. 显示目标版本、变化文件数、组件包数量及下载大小；点击下载，期间可继续使用。
3. 下载校验完成后，点击「重启并安装更新」，再次确认后退出看板、安装、自动重开。
4. 可选「自动检查并后台下载」：默认关闭，仅看板运行时检查，每 24 小时最多一次；**不会自动安装或强制重启**。
5. 安装成功后可以「恢复上一次应用版本」。恢复的是应用文件，不回退角色数据与个人设置；主动恢复会关闭自动下载。

这里的增量是**组件级增量**，不是 EXE 二进制差分。例如只改了界面，原生运行库和没有变化的图标组件不重新下载。图标分桶、数据文件分组，避免一次数据修改重下整个应用。若本地文件被修改/损坏，会把所属组件重新准备好。

### 首次迁移与发布约定

- v1.17.3 及更早版本不具备此更新器，需要先用完整包升级一次到 v1.18.0 或更高版本，之后才走应用内更新。退出旧版并备份原目录后覆盖应用文件，保留旧 `data/` 和 `tools/config.json`，不要用完整包里的空配置覆盖个人配置。
- 从 v1.18.0 起，正式 Release 同时提供完整 ZIP、`app-release.json` 和全部组件包。普通用户只需完整 ZIP 或应用内更新，不需要手动操作组件包。清单/组件缺失或网络不可用时会明确报错，不会显示“已更新”。
- 浏览器/旧桌面程序没有文件替换权限或协议，仍提供完整发布页作为兼容入口，不伪装成已自动更新。
- 原来的 `更新数据.bat` 是维护者采集/转换数据工具，**不是应用升级器**。新版本不再要求普通用户安装 Node、申请 WCL 凭证或自行抓取各站。
- 应用版本更新不代表所有上游数据都是最新或最优。各来源日期、限制与数据口径仍独立保留；不绕过 Maxroll 等来源限制。

## 安全与恢复边界

- 固定官方 GitHub Release 地址；不接受页面提供任意 URL、路径或命令。仅准确的本地 `index.html` 能调用原生更新桥。
- 每个 ZIP 和每个解压文件都校验 SHA-256 与大小；限制条目数、包体积、总大小，拒绝路径穿越、重复路径、ZIP Slip 和重解析点。
- **SHA-256 校验是完整性检查，不是发布者数字签名**；当前信任官方 GitHub 账户、HTTPS 及其发布资产。没有声称做了代码签名或离线签名验证。
- 只管理发布清单白名单中的应用文件。`data/`、`tools/config.json`、WCL 凭证、用户自建文件均不覆盖。完整包生成也会把本机 config 替换为空配置，避免发布游戏路径。
- 下载存到 `data/app-update/`，不替换运行中的文件；允许取消，已校验的 ZIP/暂存文件重试复用，不支持 ZIP 内字节级断点续传。
- 安装助手是随当前程序提供的独立 EXE，先复制到缓存，等待本应用进程退出；不强杀其他程序，不请求管理员权限。仍被占用时安装中止并恢复。
- 安装与角色扫描使用相同扫描互斥锁。替换前完整写入备份与事务日志，逐文件原子替换；**不是整个目录一次原子替换**。进程中断后，启动器会先用保留的助手恢复，再打开看板。
- 保留最近一次安装前的应用备份；安装成功后清理下载 ZIP 和暂存目录。不要在更新/恢复期间删除 `data/app-update/`。备份损坏、磁盘不可写等情况下会停止并提示，不编造恢复成功。
- 保留当前应用的一份本地备份并不能保护磁盘本身损坏；这不是个人数据备份功能。

## 维护者发布流程

1. 按现有数据来源规则获取/转换数据；执行数据验证及新更新器测试。**构建更新包不会采集游戏数据**。
2. 在 `tools/scan.ps1` 设置递增的 `X.Y.Z` 正式版本。不得重写已发布的同版本资产，也不要把开发验证的 v1.17.3 包重新发布成 v1.17.3。
3. 执行：
   ```powershell
   node tools/run-tests.js
   powershell -NoProfile -ExecutionPolicy Bypass -File tools/build-release.ps1
   ```
4. 构建会输出完整 `WowAltBoard-vX.Y.Z.zip`，以及 `WowAltBoard-vX.Y.Z-updates/`：
   - `app-release.json`：版本、协议、每个组件 SHA-256/大小、各文件路径/SHA-256/大小。
   - `update-<sha256>.zip`：确定性组件包。只允许发布文件，排除个人数据；发布清单也随完整包附带。
5. 创建 **draft** GitHub Release，tag 必须为 `vX.Y.Z`。把完整包、清单及清单所列的**所有组件包**作为该 Release 的附件上传。审核齐全后再发布为正式 latest。不要先发清单再慢慢补包，也不要只上传本次发生变化的 ZIP：用户可能从任意旧版本升级。
6. 保留旧 Release 资产，以便已取得该版本清单的用户继续下载。目标组件下载绑定版本 tag，不混用 main 分支的可变文件。

清单发现地址：
`https://github.com/Lianzy-Baimiao/WowAltBoard/releases/latest/download/app-release.json`

组件地址：
`https://github.com/Lianzy-Baimiao/WowAltBoard/releases/download/vX.Y.Z/update-<sha256>.zip`

仅允许 HTTPS 及 GitHub Release 到其资产 CDN 的限定跳转。未来扩大文件白名单或变更协议时需考虑旧更新器的兼容性，不能把不兼容清单静默发给旧客户端。

## 模块与验证

- `tools/app-updates.cs`：检查、增量暂存、白名单/校验、持久化、安装事务与恢复。
- `tools/app-update-package.cs`：维护者确定性组件构建，不负责抓取数据。完整包构建还会逐文件核对增量清单，漏收录图标/文档等发布文件时直接失败。
- `tools/app-update-worker.cs`：退出等待、独立安装/恢复、重启。
- `tools/desktop-host.cs`：固定消息桥、确认重启、进度。
- `app/app-updates.js`：界面状态，不直接访问文件系统，不热替换当前页面。
- `tools/check-app-updates.js`：独立临时目录与实际 .NET 模块，覆盖下载/校验/增量/文件占用/回退，以及子进程在替换中途退出后的恢复。
- `tools/check-app-update-browser.cjs`：真实 Edge、file:// 页面、模拟原生消息传输，检查交互及深浅主题宽度。不是公网发布测试。

开发使用的浏览器测试需要单独安装 Playwright；普通用户运行应用不需要 Node 或 Playwright。
